# 储蓄功能设计（v1.0 定稿）

> 状态：方案已冻结（评审修订 r7 已完成）　|　日期：2026-10-22
> 范围：家庭共享记账小程序「储蓄」模块的产品设计与交互流程（不含代码实现）
> 关联：《家庭记账小程序设计方案.md》《接口文档.md》

---

## 0. 一句话定义

**储蓄是家庭资产的第二本账：只记「存进去 / 取出来 / 换账户 / 校准余额」，本身不产生收入，也不产生支出，不与收支账本做任何余额校验。**

---

## 1. 边界

### 1.1 做什么

- 记录家庭共同储蓄的**余额**与**流水**（存入 / 取出 / 更新余额 / 账户转账），按**账户**拆分
- 账户实际值与账面不一致时用**更新余额**校准：只填"现在实际多少"，差额方向由系统判定
- **从储蓄支付**：记账页勾一下，同时生成「一笔支出 + 一笔取出」
- **收入到账即存**：记收入时顺手存入储蓄
- 与收支**互不校验**：不显示差值、不做账外资金提示

### 1.2 不做什么

- **不做收益/利息记账**：不推算市值、不自动计息、不产生任何收支；余额只在用户主动「更新余额」时被校准（决策 10、11）
- 不做期初余额、「现金/银行卡」等外部账户，也不计算"手头 = 累计结余 − 储蓄余额"（决策 5、10）
- 不做**攒钱目标**（后续再议，见 11）
- 不把储蓄记录混进收支明细页

## 2. 决策清单（冻结）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 形态 | 储蓄是**独立模块**：余额 + 流水为底座，按账户拆分；不与收支账本做余额校验；不引入攒钱目标（见 11） |
| 2 | 收支口径 | 存入 / 取出 / 账户转账**完全不进收支**；储蓄本身不产生任何收入或支出记录（唯一例外：从储蓄支付会同时生成一笔支出，见 6.5） |
| 3 | 入口 | 首页 Hero 下方储蓄卡 + 独立二级页，不动 tabBar |
| 4 | 权限 | 全员可存入 / 取出 / 从储蓄支付 / 账户间转账 / 更新余额；仅 owner 管理账户（新建/改名/停用/删除，且**只能针对自定义账户**；预置账户全局只读） |
| 5 | 账户模型 | 储蓄按账户建模：5 个预置 + 家庭自定义；每笔储蓄流水都必须落到某个账户（未选择时默认「活期」）；**不单独设「现金」账户**——现金与活期合并，记在同一账户里 |
| 6 | 账户模式 | 预置 5 个：**活期（默认）、定期、国债、基金、保险**；家庭自定义（**自定义上限 20，账户总数最多 25**）；预置**不可删、不可改名、不可停用**（全局只读） |
| 7 | 账户删除 | 余额 > 0 禁止删除，提示先转出；余额为 0 时逻辑删除，历史记录保留账户名 |
| 8 | 跨模块联动 | 只有两处，且都发生在**记账页**：① 支出表单「从家庭储蓄支出」→ 一次写「支出 + 取出」，成对维护；② 收入表单「同时存入家庭储蓄」→ 一次写「收入 + 存入」。储蓄页自身不产生任何收支 |
| 9 | 取出 | 保留独立动作；按该账户余额扣减，**超过余额硬阻断**；取出自身不记收支 |
| 10 | 不做收益记账 | 不推算市值、不自动计息、**不产生任何收入或支出**；不计算"手头"、不做账外资金与漏记收入提示；不新增「理财」「投资亏损」等收益分类 |
| 11 | 更新余额（余额校准） | 账户级手动操作：只填**当前实际余额**，差额方向由系统判定（多出 → 存入、少了 → 取出），生成一条带 `source=adjust` 标记的流水；**不产生收入/支出，累计结余不变**；金额不可编辑（只能删除重来）；同一账户 24h 内二次校准需二次确认 |

## 3. 概念模型

### 3.1 两本账

| 账本 | 记录方式 | 由谁维护 |
|---|---|---|
| 收支账本 | `transaction`（收入 / 支出） | 用户手动记 |
| 储蓄账本 | `saving_record` | 存入 / 取出 / 更新余额 / 账户转账（+ 记账页两个开关） |

**两本账各自独立**：收支账本算"净攒下多少"，储蓄账本算"存进去多少、还剩多少"。系统不比较两者、不派生"手头"、不做余额校验——用户很可能没记全（记账前存款、部分现金收入），差值校验只会误报。唯一接触点是**记账页的两个开关**（决策 8），储蓄页自身的操作不产生收支。

### 3.2 四个动作（+ 一个记账页联动）

| 动作 | 语义 | 收入 | 支出 | 储蓄余额 | 生成记录 |
|---|---|:--:|:--:|:--:|---|
| 存入 | 往储蓄里放钱 | — | — | **+** | 存入 ×1 |
| 取出 | 从储蓄里拿钱（尚未花掉） | — | — | **−** | 取出 ×1 |
| 更新余额 | 账户实际值和账面不一致时校准：只填实际余额，**差额方向由系统判定** | — | — | **±差额** | 存入或取出 ×1（`source=adjust`，标「余额调整」） |
| 账户转账 | 储蓄内部换账户 | — | — | **0** | transfer_out ×1 + transfer_in ×1（link_id） |
| （联动）从储蓄支付 | 在**支出表单**里勾选，钱从储蓄出 | — | **+** | **−** | 支出 ×1 + 取出 ×1（绑定） |

> 「从储蓄支付」是**记账页**的动作，不属于储蓄页；它存在的唯一理由是"钱花了必须记支出"，避免用户先取出、又忘了记支出。
> **更新余额不是收益记账**：它只是把"账面"调成"实际"，不产生收入/支出、不改变累计结余（决策 10、11）。

### 3.3 为什么储蓄不记收益

产品定位是**记录每天的流水**（发了工资、买了空调）。储蓄只是独立模块，回答"一共存进去多少、还剩多少"。

1. **收益不是流水**：利息、分红、浮盈浮亏不是某一天的一笔进出；逐日估值要接银行/基金数据源，家庭账本做不到。
2. **记了就要有口径**：收益一旦进收入，就得回答"取出时本金与收益怎么拆""亏损记哪一类""账外资金怎么解释"——每一条都要新增规则、分类和组合记录，还会牵连预算与统计。
3. **用户不关心，而且反直觉**：核心诉求是"钱花哪了 + 攒了多少"；基金涨 800 就让"本月收入"多 800，多数人不认为这是收入。

**结论**：系统不推算收益，但用户可以主动「更新余额」把账面调成实际值，差额只留在储蓄账本内（决策 11）——**系统不猜，用户说了才算**。想看投资收益属于另一个功能（资产视图），应基于独立模块扩展。

## 4. 数据模型

金额一律为**整数分**；时间统一 `Asia/Shanghai`。

### 4.1 `saving_account`（储蓄账户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 自增主键 |
| family_id | BIGINT NULL | NULL = 系统预置（全局），与 `category.family_id` 同套路 |
| name | VARCHAR(32) | 账户名，如「活期」「国债」 |
| icon | VARCHAR(32) | emoji |
| color | VARCHAR(16) | 配色（十六进制） |
| sort | INT | 排序，越小越靠前（预置账户固定 1–5，不可调整） |
| is_system | TINYINT(1) | 0=家庭自定义，1=系统预置 |
| status | TINYINT(1) | 1=启用，0=停用（**仅自定义账户可停用**；停用后不出现在存取选择列表，余额仍计入总额） |
| deleted | TINYINT(1) | 逻辑删除标记（MyBatis-Plus 全局 logic-delete-field） |
| created_at / updated_at | DATETIME | |

**约束说明（重要）**：

- **不加 `UNIQUE(family_id, name)`**。两个原因：① 逻辑删除的行仍占用唯一键，会导致"删掉账户后无法再建同名账户"；② MySQL 唯一索引对 `family_id IS NULL`（系统预置）不生效。
- 重名校验放应用层：新建/改名时查同家庭未删除账户，冲突提示"该账户名已存在"。极小概率并发重名不影响资金正确性（余额按 account_id 聚合，不按名称）。

### 4.2 `saving_record`（储蓄流水，唯一资金事实来源）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT | 自增主键 |
| family_id | BIGINT | 所属家庭 |
| account_id | BIGINT | 所属账户，必填（存入/取出/支付/转账时由用户选择，默认「活期」） |
| direction | VARCHAR(16) | `in` 存入 / `out` 取出 / `transfer_in` 转入 / `transfer_out` 转出 |
| source | VARCHAR(16) | `normal`（默认，真实资金进出）/ `adjust`（由「更新余额」生成，标「余额调整」） |
| amount | INT | 金额（分），恒为正，方向由 `direction` 表达 |
| date | DATE | 业务日期（**统计"本月存入/取出"按此字段**，与账单口径一致） |
| note | VARCHAR(200) | 备注（写用途或来源，如"买入国债""春节旅行"） |
| openid | VARCHAR(64) | 操作人 |
| operator_name | VARCHAR(32) | 操作人昵称快照（写入时冗余）。`family_member` 在成员退出时物理删行，历史流水靠它展示「谁记的」，不依赖成员行存在（见 8.4） |
| link_id | VARCHAR(40) NULL | 组合记录关联键（两条记录互相指向，见 4.3） |
| linked_transaction_id | BIGINT NULL | 关联的账单记录 id（仅「从储蓄支付」「到账即存」两处跨表联动使用） |
| created_at / updated_at | DATETIME | |

索引：`KEY idx_family_date (family_id, date)`、`KEY idx_family_account (family_id, account_id)`、`KEY idx_link (link_id)`、`KEY idx_linked_tx (linked_transaction_id)`。

**删除语义**：物理删除（与 `transaction` 一致），**无 `status` 作废状态**；组合记录必须成对删除（见 8.3）。

### 4.3 三条硬规则

1. **余额永远派生**：`余额 = Σ(存入 + 转入) − Σ(取出 + 转出)`，不落 `balance` 字段。并发、编辑、删除都不会让余额漂移。
2. **转账零和**：一次转账写两条金额相同、方向相反的记录（`transfer_out` / `transfer_in`），共享 `link_id`，对总余额净影响为 0；不计入「本月净增」。
3. **组合记录原子化**：组合只能成对删除/修改。**同一张表内**的组合（账户转账的两条 `saving_record`）用 `link_id` 关联；**跨表**的组合（「从储蓄支付」的支出 ↔ 取出、「到账即存」的收入 ↔ 存入）用 `saving_record.linked_transaction_id` 关联，账单侧通过该字段反查是否属于某个组合。

> **为什么余额不落库**（有意为之）：余额是流水的推论，落库就出现第二个事实来源——并发要加锁、编辑/删除要同步扣减、脚本修数后需人工对账、还要定时 `SUM` 校验。家庭最多 25 个账户、单账户几千条流水，`SUM` 走 `idx_family_account` 是毫秒级，没有落库的必要。若将来读性能真成瓶颈，加 `balance_cache`（同事务更新 + 定时校验 + 以流水为准重建），**不把缓存当可直接编辑的余额**。

> **为什么允许改金额、不允许改方向**：改金额是更正录错，余额自动重算；`in` / `out` 决定资金流向，改了就是另一笔业务，只能删除后重录（8.2）。变更痕迹由 `updated_at` + `openid` 提供。**例外**：`source=adjust` 的调整金额不可改（它是"当时账面与实际之差"），只能删除后重新「更新余额」；日期与备注仍可改。

### 4.4 预置数据

**储蓄账户（5 条，`family_id=NULL`、`is_system=1`）**

| name | icon | 说明 |
|---|---|---|
| 活期 | 💵 | **默认账户**（`sort=1`）；用户未选择时默认落在此。现金与活期不再拆分 |
| 定期 | 🏦 | 银行定期存款 |
| 国债 | 📜 | 国债、大额存单等低风险固定收益 |
| 基金 | 📈 | 货币基金、债券基金、权益基金 |
| 保险 | 🛡️ | 储蓄型保单（增额终身寿、年金等）；纯保障型消费险不入账 |

> **为什么去掉「其他」**：5 个预置已覆盖家庭常见的钱存放形态；「其他」与自定义账户职能重叠，最容易变成"什么都往里塞"的垃圾桶，且会让「按账户筛选余额」失去意义。确实需要就由家庭自建一个。

> **保险账户的余额口径是「现金价值」**，不是保额：储蓄型保单按退保可得的现金价值记账，退保 / 减保后用「更新余额」校准（6.9）；纯保障型消费险不入账。

> **不新增任何分类**：储蓄不产生收支，因此不需要「理财」「投资亏损」这类专用分类。「从储蓄支付」产生的支出由用户自选普通分类（如「家电」「餐饮」）。

## 5. 数字口径

### 5.1 公式

```
本月结余     = 本月收入 − 本月支出                       ← 储蓄不参与
累计结余     = Σ历史收入 − Σ历史支出                     ← 只算 status=1 的有效流水
本月净增     = Σ本月存入 − Σ本月取出（含「从储蓄支付」与「更新余额」的流水；转账不计）
储蓄余额     = Σ(存入+转入) − Σ(取出+转出)              ← 存取净额；只在用户「更新余额」时被校准
```

> **两本账不做交叉计算**（决策 10）：不算 `累计结余 − 储蓄余额`，也不提示"手头不够/可能漏记收入/账外资金"。用户很可能没记全（记账前的存款、部分现金收入），差值校验只会把正常记账判成"账错了"；**储蓄余额大于累计结余是正常状态**（5.2 场景 D）。单账户视角下 `各账户余额之和 = 储蓄余额`（停用账户也计入）。

统计"本月"一律按 `saving_record.date`（业务日期）与 `transaction.date`，不用 `created_at`；累计口径只统计 `transaction.status=1` 的有效流水。

### 5.2 场景验算

> 场景按**储蓄余额总额**表述；期初值由更早的流水累计而来，**不是用户填写的期初余额**（1.2）。

**场景 A：存取不影响收支（新建家庭，期初结余 0、储蓄 0）**

本月收入 10,000、支出 6,000、存入 3,000、取出 1,200

| 账本 | 数值 |
|---|---|
| 收支：收入 / 支出 / 结余 | 10,000 / 6,000 / **4,000** |
| 储蓄：本月存入 / 取出 | 3,000 / 1,200 |
| 本月净增 | **+1,800** |
| 期末储蓄余额 | **1,800** |

说明：存取一笔都不进收支——收入仍是 10,000，支出仍是 6,000，预算与分类占比不受影响。

**场景 B：从储蓄支付 8,000（期初：累计结余 20,000、储蓄 12,000）**

在支出表单勾选「从家庭储蓄支出」，一次写两条：支出 8,000 + 取出 8,000

| 账本 | 数值 |
|---|---|
| 收支：本月支出 | **+8,000** |
| 收支：累计结余 | 20,000 − 8,000 = **12,000** |
| 储蓄：期末余额 | 12,000 − 8,000 = **4,000** |
| 本月净增 | **−8,000**（含「从储蓄支付」的取出） |

说明：钱真花了，所以必须出现在支出里；取出只是让储蓄余额跟着减少。这是唯一会让两本账同时变化的操作。

**场景 C：账户转账 5,000（国债 → 活期，期初储蓄 12,000）**

| 账本 | 数值 |
|---|---|
| 储蓄：国债 / 活期 | 5,000 → 0、7,000 → 12,000 |
| 储蓄：总额 | **12,000（不变）** |
| 收支 | 完全不受影响 |
| 本月净增 | **不变**（转账不计） |

说明：写两条方向相反的流水、共享 `link_id`；删任一条则两条一起消失。

**场景 D：储蓄余额大于累计结余，也正常（记账前已有存款）**

家庭记账前就有 2 万存款，只记了收入 10,000、支出 5,000；期间把这 2 万存入储蓄。

| 账本 | 数值 |
|---|---|
| 累计结余 | 10,000 − 5,000 = **5,000** |
| 储蓄余额 | **20,000** |
| 系统反应 | **不提示、不校验、不解释** |

说明：这里若做差值校验会算出负数并误报"账外资金"；两本账各自成立即可（决策 10）。

**场景 E：更新余额（账户实际值与账面不一致）**

期初：累计结余 20,000、储蓄 12,000（全在「基金」）。用户打开基金 App，看到市值 13,000。

| 账本 | 数值 |
|---|---|
| 操作 | 储蓄页选中「基金」→「更新余额」→ 只填 `13,000` |
| 系统判定 | δ = 13,000 − 12,000 = **+1,000** → 自动记「存入 1,000」（`source=adjust`，标「余额调整」） |
| 储蓄余额 | **13,000** |
| 累计结余 | **20,000（不变）** |
| 本月净增 | **+1,000**（含余额调整） |
| 收支 / 预算 | **完全不受影响** |

反向同理：若实际值是 11,400 → δ = −600，自动记「取出 600」，储蓄余额 11,400、本月净增 −600。

说明：用户只填"现在实际多少"，方向与金额都由系统算；这笔差额只存在于储蓄账本，不产生收入或支出（决策 11）。

```
┌──────────────────────────────────────┐
│ 家庭储蓄                  ¥12,000.00 ›│
│ 本月 +3,000 · 取出 −1,200             │
│                          [ 存入 ]     │
└──────────────────────────────────────┘
```

- **位置**：Hero（绿色本月概览）下方、**「今日」卡上方**。视觉上必须与下方两张白卡区分——用 `--brand-soft` 浅绿底或左侧 6rpx 绿色竖条 + 💰 图标，**不加卡片阴影**；否则首页会变成「绿-白-白-白」四段同权堆叠，储蓄卡被夹在中间淹没
- 卡片只有**储蓄余额**与**本月存取**：不与收支账本比较、不展示差值、不做任何校验提示（决策 10）
- 副标题口径：`+` 为本月存入（含「更新余额」的调整），`−` 为**本月全部取出（含「从储蓄支付」与「更新余额」的取出）**，转账不计
- 无任何记录：卡片显示「还没有储蓄，开始存第一笔 →」
- 点卡片 → 储蓄页；点「存入」直接拉起存入弹层
- **点击区嵌套**：卡片整体可点，「存入」按钮必须 `catchtap` 阻止冒泡——否则一次点击会同时拉起弹层并跳转储蓄页；按钮四周留 ≥16rpx 空白，两个点击区不重叠
- 余额用等宽数字（`font-variant-numeric: tabular-nums`），保存后刷新时数字不左右抖动

### 6.2 储蓄页

自上而下：**余额卡（储蓄余额 + 本月存取）** → **账户区（按账户余额 + 转账入口）** → **按月分组的流水**；「存入 / 取出」做成**底部固定操作条**（带 `safe-area-inset-bottom`），不再夹在账户区和流水之间——否则流水可视区被压到不足一屏的 1/3。

账户区：横向滚动的账户卡（图标 + 名称 + 该账户余额），首个为「全部」——「全部」卡只显示「全部」+ `共 N 个`，**不重复显示总额**（总额已在余额卡上，同屏出现两次会让横滚区变重）；点某张卡即按该账户筛选余额与流水，点「全部」回到总额。**停用账户仍保留在筛选列表**（置灰 + 标「已停用」，可点击查看历史流水），只有新增存取 / 支付 / 转账的选择列表排除它（6.7）。账户区右上**只放「转账」**（6.8），「账户管理」（6.7）移到页面导航栏右上角，避免与横滚账户卡挤在同一行；余额卡上另有一条**常驻**文字链「余额不对？更新余额」（6.9）——选中具体账户时直接进表单，「全部」视角下先弹账户选择。切换账户后流水**回到分页起点**，不保留滚动位置（否则会停在筛选后可能是空白的位置）。

**余额卡标题随筛选变化**：选中具体账户时标题换成账户名 + 「单账户余额」，数字为该账户余额；回到「全部」恢复「家庭储蓄」+ 副标题 `共 N 个账户`——否则用户会把单账户余额误读成总额。

流水行**分两行**（375 宽度下六个字段放不进一行）：

```
[🍊] 取出 −1,200.00                买冰箱
     10-18 · 国债 · 妈妈
```

主行 32rpx 金额（存入绿 `+` / 取出橙 `−` / 转账灰）+ 右对齐备注；次行 24rpx 灰字 `日期 · 账户名 · 操作人`；**账户名超过 6 字截断**（自定义账户名上限 32 字，否则挤压金额换行）。按 `date desc, id desc` 分页；点击可编辑/删除（本人或 owner）。

月份分组头右侧显示当月小计 `+3,000 / −1,200`，口径与首页卡片副标题一致（存入含调整、取出含「从储蓄支付」，转账不计）。

**与明细页的骨架复用**（不另造一套列表）：行结构直接沿用 `pages/detail` 的 `.trans` 两行式（`.ic` 图标 + `.mid` → `.line1` 分类/金额 + `.note` 副行），方向图标替代分类图标、`.note` 放 `日期 · 账户名 · 操作人`；月份分组头与当月小计复用 `.date-head` / `.day-sum` 样式，只把「10-18 周六」换成「2026年10月」。分组粒度保持**按月**：储蓄流水稀疏，「本月净增」才是用户要看的数，与明细的按日分组刻意不同，不强行统一。

**可编辑范围**（点击流水行 → 编辑；删除规则见 8.3）：

| 记录类型 | 可改 | 禁止 |
|---|---|---|
| 普通存入 / 取出 | 金额、业务日期、备注、**账户**（改账户即把该笔记到另一个账户，受新账户余额非负校验） | 方向（`in` ↔ `out` 只能删除后重录） |
| 组合记录（从储蓄支付 / 到账即存） | 金额（「从储蓄支付」调大上限 = 该账户**当前余额** + 原取出金额，超限阻断）、业务日期（**两侧强制同步**）、各自备注（**不联动**） | 方向、**储蓄账户**（换账户会让取出落到另一个账户上，等于绕过余额上限）、单独改另一侧金额或日期、解除绑定（要解绑只能删除组合后重录） |
| 余额调整（`source=adjust`） | 业务日期、备注 | **金额**（改了就不再是当时的校准结果）、方向、账户（只属于该账户；要换账户请删除后重新更新余额） |

- **编辑组合记录时，记账弹层里的开关转只读**：勾选态置灰且保持开启，右侧显示「已从 国债 取出 ¥8,000」，下方一行提示「改为现金支付请删除后重新记录」；账户选择同样只读展示、不可切换（储蓄账户不可改）。避免"关掉开关 = 解绑"与 6.2 的解绑规则冲突。
- **关联账单已作废（成员退出）时，保留下来的储蓄流水转只读**：不可编辑、不可删除，「关联账单」入口隐藏或置灰为「关联账单已作废」。否则 owner 删掉这条取出会让余额回退，账实不符（见 8.4）。
- 组合记录的**业务日期必须两侧一致**：账单日期与储蓄日期不同会让「本月支出」与「本月净增」跨月错位，保存时强制同步 `date`。**时间（`time`）只存在于账单侧**——记账表单有日期 + 时间，`saving_record` 只有 `date`，不要给储蓄表加 `time` 列，跨月判断与统计口径一律按 `date`。
- 备注两侧各自独立（账单备注写"买冰箱"、储蓄备注写"春节前大件"这类差异是合理的），不做联动。
- 编辑后统一校验：余额非负（8.2）、预算重算、分类占比重算。

### 6.3 存入

- 金额键盘 + 快捷 `¥500 / ¥1,000 / ¥2,000`
- 账户：默认「活期」；若账户区已选中具体账户，则默认该账户，可切换
- 日期（默认今天）、备注（提示：可写"买入国债""年终奖"等来源/用途）
- **不做任何余额校验或提示**：存多少都允许，不与收支账本比较（决策 10）
- 成功：余额 +，流水 +，首页卡片同步

### 6.4 取出

- 账户：默认当前选中的账户；「全部」视角下需先选账户（默认「活期」）
- 顶部展示「可取出 ¥12,000」（= **该账户**余额，不是总额）
- `金额 > 该账户余额` → 即时标红 + 按钮置灰（**硬阻断**），提示可取出金额
- 取出只减该账户余额，**不产生收入或支出**；钱之后怎么花，另记一笔支出或勾「从家庭储蓄支出」
- 固定文案：「取出本身不产生支出，等真正花掉时再记一笔支出；若现在就付款，请用『从家庭储蓄支出』」
- **账户实际值和账面不一致 → 用「更新余额」（6.9）**：取出只按账面余额扣减，不承担估值职责

### 6.5 从储蓄支付（记账弹层内）

- **开关的插入位置**：支出表单里的一行开关 `从家庭储蓄支出`，放在**金额输入之后、信息卡（日期 / 时间 / 备注）之前**。用户先输金额、再决定支付方式、立刻看到「支付后剩余」，反馈闭环最短；放表单最底部会隔着凭证图片区，关联性丢失
- 现有 `components/record-sheet` 表单顺序为：分类行 → 金额 → 信息卡 → 凭证图片 → 保存 → 删除；开关与折叠卡插在「金额」与「信息卡」之间
- 默认账户 = **本家庭上次在记账页用过的储蓄账户**，无记录才落到「活期」；与储蓄页当前浏览的账户**无关**。下方的余额预览一律取**所选账户**的余额，不是总额
- 账户选择 + 余额预览做成开关下方的**折叠卡**（**两行**、展开高度 ≤ 120rpx：上行 `💵 活期 ›`，下行 `余额 ¥12,000 → 剩余 ¥4,000`）；单行装不下「账户名 + 余额 + 剩余」三个元素。**余额预览不单独开浮层**。`record-sheet` 表单已在 `scroll-view` 内且 `max-height: 88vh`，展开后靠滚动即可，无需加高弹层
- **账户选择的形态**：点折叠卡 → **半屏账户面板**（复用 `prompt-dialog` 的遮罩与滑入），列表项 = 图标 + 账户名 + 该账户余额 + 选中勾；账户最多 25 个，**不要用 `picker`**（25 项滚轮无法使用）
- 该账户余额不足：预览区变红（`当前余额 ¥12,000 → 不足 ¥3,000`）、金额输入框描边红、主按钮置灰但**不隐藏**，点击提示「该账户最多可支付 ¥12,000」；前端 + 事务内后端二次校验
- 保存：一次写入 **支出 + 储蓄取出**，通过 `saving_record.linked_transaction_id` 绑定该支出；明细页该笔支出带「储蓄」小标
- **编辑金额**：取出金额恒等于支出金额，两侧同步调整。调大时的上限 = 该账户**当前余额** + 原取出金额（最多把账户取空）；超限阻断并提示「最多可改为 ¥X」，同时给两个出路：**先存入再改**，或**改从其他账户支付**（需删除后重新记）
- 只改备注 / 日期不触发余额校验；改日期跨月时两侧同步，并重算原月份与新月份的预算与统计；金额必须 > 0
- **储蓄账户不可改**：组合记录一旦建立，取出所属账户固定（换账户等于另一笔取出），要换账户只能删除后重录
- 编辑时若查不到配对的取出（关联记录已不存在）→ **拒绝保存**并提示「该支出关联的储蓄取出已不存在，请删除后重新记录」，不静默当成普通支出（否则支出改了、储蓄余额不变，两本账脱节）
- 后端二次校验用**账户余额原子扣减**（`WHERE balance >= ?` / 行锁）而非「先查余额再写」，避免两笔并发同时通过；前端提示与后端错误共用同一句「最多可改为 ¥X」
- 该开关只出现在**支出**表单；收入表单对应 6.6 的「同时存入家庭储蓄」，二者互斥，不会同时出现

### 6.6 收入到账即存（记账页开关）

> 这是**收入侧的开关**：收入发生的那一刻顺手决定"要不要同时存进储蓄"。它不是储蓄动作，也不是储蓄页的按钮，储蓄模块本身不关心这笔收入从哪来。

- 记账页记一笔收入（工资、奖金、红包…），底部开关 `同时存入家庭储蓄`，一次生成 `收入 + 存入`（通过 `linked_transaction_id` 绑定）；不勾则只记收入（钱到卡里、可能被花掉）
- **全部分类同一套文案**（见决策 8）
- 勾选后出现**账户选择**（默认口径与 6.5 一致：本家庭上次在记账页用过的储蓄账户，无记录才落到「活期」，**不跟随储蓄页浏览态**），生成的「存入」落在该账户
- 该开关只出现在**收入**表单；支出表单对应 6.5 的「从家庭储蓄支出」，二者互斥、不会同时出现

```
记账页 → 记一笔「工资」收入   ¥10,000
  ☑ 同时存入家庭储蓄
  → 本月收入 +10,000，储蓄余额 +10,000，本月净增 +10,000
```

### 6.7 账户管理（仅 owner）

- 入口：储蓄页**导航栏右上角「管理」** → 账户管理页；与账户区右上的「转账」分开，避免三个入口挤占横滚账户卡的行宽（6.2）。成员可见入口，点击提示「由创建者管理账户」
- 列表：按 `sort` 升序，每行 `图标 · 账户名 · 当前余额 · 记录数`；预置账户带「预置」标签且无改/停/删入口，停用账户置灰并标「已停用」
- 新建：图标（emoji）+ 名称（1–32 字，同家庭未删除账户去重，重名提示「该账户名已存在」）+ 排序；**自定义账户上限 20**（另有 5 个预置，账户总数最多 25），达到上限禁用新建并提示「最多 20 个自定义账户」
- 改名 / 改图标 / 调排序：随时可改，不影响历史流水（流水按 `account_id` 关联，名称仅展示）
- 停用（**仅自定义账户**）：**不再出现在新增存取 / 支付 / 转账的选择列表**，但余额仍计入 `储蓄余额` 总额（8.7）；储蓄页的账户筛选区**保留**该账户（置灰 + 标「已停用」），历史流水仍可查看（6.2）；可随时重新启用
- 删除：**余额 > 0 时禁止**，提示「请先转出到其他账户」；余额 = 0 时逻辑删除，历史流水仍展示账户名（8.7）；预置账户**不可删除、也不可停用**（只能使用或另建自定义账户）

### 6.8 账户转账

- 入口：储蓄页账户区右上角「转账」；**启用账户不足 2 个时按钮置灰**，点击提示「至少需要两个启用的储蓄账户」
- 表单：`从账户`（默认当前选中账户）→ `到账户`（默认下一个启用账户）+ 金额 + 业务日期 + 备注
- 校验：
  - 从/到账户不能相同（选同一账户时「到账户」列表里置灰该项）
  - `金额 > 从账户余额` → 硬阻断，展示该账户可转出金额（事务内二次校验，8.1）
  - 任一端停用或已删除 → 不出现在选择列表
- 保存：一次写 **两条** `saving_record`——`transfer_out`（从账户）+ `transfer_in`（到账户），金额相同、共享 `link_id`（4.3 规则 2）
- 结果：`储蓄余额` 总额不变，不计收入/支出，不计入「本月净增」，不影响预算与统计（决策 2）
- 编辑/删除：成对生效，改金额则两条同步改，删除则两条一起删；**方向不可改**（`transfer_out` ↔ `transfer_in` 不允许互换）
- 不提供「收益」概念：转账只是换账户，不产生收入或支出

### 6.9 更新余额（余额校准）

用于「账户实际值和账面不一致」：利息到账、基金涨跌、银行结息，或用户之前漏记了某笔。**只填实际余额，差额方向由系统判定**，用户不需要自己算。

- 入口（两条，同一表单）：① 储蓄页余额卡上的**常驻**文字链「余额不对？更新余额」——选中具体账户时直接进表单，「全部」视角下先弹账户选择；② 选中具体账户时账户区右上的「更新余额」。停用账户不显示入口。之所以做成常驻，是避免用户找不到校准入口而用「存入 / 取出」凑数，污染 `source=adjust` 语义与「本月净增」
- 表单：`账面余额 ¥12,000`（只读）+ 输入框 `当前实际余额` + 业务日期（默认今天）
- 差额：`δ = 当前实际余额 − 账面余额`
  - `δ > 0` → 自动生成 **存入 δ**（`source=adjust`，标「余额调整」）
  - `δ < 0` → 自动生成 **取出 |δ|**（同上）
  - `δ = 0` → 提交按钮置灰，提示「余额没有变化，无需更新」
- 确认弹层（提交前必须展示）：

```
账户：基金        账面 ¥12,000 → 实际 ¥13,000
差额：+¥1,000  →  将记一笔「存入 1,000（余额调整）」
                 只影响储蓄余额，不影响收入/支出
☐ 我确认这是账户当前的实际余额（必须勾选才能提交）
```

- **不产生收入或支出**：累计结余、预算、分类占比、明细页都不受影响，差额只存在于储蓄账本（决策 11）
- **流水展示**：带「余额调整」标签，可按 `source=adjust` 筛选，用于区分"真存进去的钱"与"账户自己涨的"
- 结果：该账户余额变为输入值；储蓄余额总额 ±δ；本月净增 ±δ
- 编辑/删除：**金额不可编辑**（见 6.2），只能删除后重新校准；删除后余额自动回退
- 频率：同一账户 24 小时内第二次校准需二次确认，提示上次校准时间与差额
- 不提供：负数输入、自动/定时校准（系统不推算收益）、按收益率反推

### 6.10 页面状态

| 状态 | 表现 |
|---|---|
| 空态 | 插画 + 「开始存第一笔」 |
| 仅有预置账户 | 正常余额卡；账户区显示「全部 + 5 个预置」+「管理」入口 |
| 达自定义账户上限（20） | 管理页新建按钮置灰，提示「最多 20 个自定义账户」 |
| 「全部」视角 | 余额卡显示储蓄余额总额与本月存取，账户卡可横向滚动 |
| 某账户余额为 0 | 该账户卡仍展示，取款表单里选中后提示「该账户没有余额」 |
| 取出金额超过账户余额 | 即时标红 + 提交按钮置灰（6.4） |
| 选中具体账户 | 余额卡常驻文字链 + 账户区右上出现「更新余额」（6.9） |
| 「全部」视角 · 更新余额 | 文字链仍可见，点击先弹账户选择再进表单（6.9） |
| 实际余额与账面一致 | 「更新余额」提交按钮置灰，提示「余额没有变化」 |
| 同一账户 24h 内二次校准 | 可提交，但弹层多一次二次确认，显示上次校准时间与差额 |
| 支付金额超过所选账户余额 | 预览区变红「不足 ¥X」+ 输入框描边红 + 按钮置灰（不隐藏），点击提示上限（6.5） |
| 编辑组合记录 | 记账弹层里的「从储蓄支付 / 同时存入」开关为只读态，储蓄账户不可切换（6.2） |
| 关联账单已作废（成员退出） | 该储蓄流水转只读，「关联账单」入口隐藏或标「关联账单已作废」（6.2、8.4） |
| 启用账户仅 1 个 | 转账按钮置灰，点击提示「至少需要两个启用的储蓄账户」（6.8） |
| 存在停用账户 | 筛选区保留该账户卡（置灰 + 「已停用」），可点击筛选历史流水（6.7） |
| 后端校验失败（余额不足 / 超上限） | 表单**保留已填内容**，仅高亮金额输入框 + toast 提示，不清空重填 |
| 首屏加载中 | 余额卡与账户区显示**骨架屏**，不显示 `¥0.00`（避免数字从 0 跳变） |
| 流水分页加载中 | 列表底部「加载中…」；到底显示「没有更多了」，不留空白 |
| 页面加载失败 | 整块错误态 + 「重试」按钮，不只用 toast 后留白 |
| 保存中（含「从储蓄支付」事务写入） | 主按钮变 loading 且**防重复点击**，直到请求返回；失败则恢复可点 |

**通用交互约定**（实现时统一执行，不再逐条讨论）：

- 金额一律以整数分存储、展示两位小数；输入最多两位小数，单笔上限 ¥9,999,999.99，超长 / 负数 / 非法字符直接拒绝；
- **金额输入沿用系统数字键盘**（`record-sheet` 现有 `type="digit"` + `kbHeight` 手动避让 + `adjust-position="{{false}}"` + 表单外层 `scroll-view`）；**不自建键盘**——那会推翻这套已调好的避让逻辑，收益不匹配成本。仅需补：小数最多两位、非法字符过滤、`saving` 时拦截重复提交；
- **保存按钮保持在表单流末尾**（沿用 `record-sheet` 现状，后面跟「删除这笔」），不做底部固定；保存中切 spinner 并拦截点击（现状已有 `saving` 态，补拦截即可）；
- 所有金额用**等宽数字**（`font-variant-numeric: tabular-nums`），输入与刷新时不抖动；
- **快捷金额只在「存入」出现**（`¥500 / ¥1,000 / ¥2,000`）；取出与「从储蓄支付」用「全部取出 / 全部可用」（上限是动态的，固定金额无意义）；
- 保存成功后统一用 `onShow` 重新拉取数据（首页储蓄卡、储蓄页、明细、统计、预算），不做跨页事件广播；
- 明细页「储蓄」小标点击 → 跳储蓄页并定位到对应取出流水（路由带 `saving_record.id`，定位后高亮该行）；
- 破坏性操作（删除组合记录 / 删除账户）的确认弹层必须写明受影响对象、金额与余额前后值，例如：`删除这笔支出将同时撤销「国债」账户的取出 ¥8,000，该账户余额从 ¥4,000 回到 ¥12,000。`；
- **颜色语义**：存入绿（`+`）、取出橙（`−`）、转账灰；「从储蓄支付」的取出同为橙色并带「储蓄」小标（与明细页账单侧小标呼应）；`source=adjust` 用灰字 + 「余额调整」标签，三种取出在流水里一眼可分

### 6.11 与现有组件 / 样式的复用约定

储蓄模块**不新建视觉体系**，全部复用现有套件（这是本设计能在现有小程序里低成本落地的前提）：

| 需求 | 复用对象 | 说明 |

| 页面骨架 | `.page` / `.page-body` / `.pad` | 储蓄页是二级页（`navigateTo`），无自定义 tabBar、无 FAB |

| 账户选择 | `prompt-dialog` 的遮罩 / 滑入动画 | 半屏面板，不用 `picker` |
| 流水列表 | `pages/detail` 的 `.trans` / `.date-head` / `.day-sum` | 两行式行骨架与分组小计直接沿用 |
| 明细页「储蓄」小标 | `.tx-img-tag`（现有「有凭证」标签） | 并排插入，不新做样式 |
| 按钮 | `.btn` / `.btn-primary` / `.btn-sm` | 92rpx ≈ 46px，满足 44pt 触控下限 |
| 记账弹层 | `components/record-sheet` | 支出 / 收入表单只加开关与折叠卡，不改结构 |

**颜色 token（需在 `app.wxss` 补登记）**：

- 现有 `--income: #07C160`、`--expense: #fa5151`、`--warn: #ffb020`，**没有橙色**；
- 新增 `--saving-out`（建议 `#ff8f1f`）用于「取出 / 从储蓄支付」；存入用 `--income`；转账用 `--text-3` 灰；
- **硬约束**：储蓄页与储蓄流水一律不用 `--expense` 红——取出不是支出，混用会让"少了一笔钱"与"花了一笔钱"在视觉上无法区分。

**触控热区**：文字按钮（「余额不对？更新余额」「转账」「管理」）视觉可以小，但热区高度 ≥ 88rpx（≈44pt）；账户卡宽度 ≥ 200rpx、高度 ≥ 140rpx。

**列表与滚动（项目已有教训）**：`app.wxss` 明确注释——内容层套 `overflow-y:auto` 会让 canvas 2d 同层渲染退化成原生浮层、盖住自定义 tabBar。因此：账户区用 `scroll-view scroll-x` **只包账户卡**；流水列表**不包滚动容器**，走整页滚动 + `onReachBottom`（与明细页一致，20 条/页）。

**底部占位**：储蓄页的固定操作条会盖住最后一条流水，需新增 `.action-clear`（约 180rpx + `env(safe-area-inset-bottom)`）；现有 `.tab-clear`（440rpx）是为 tab 页 FAB 预留的，两者不要混用。

## 8. 边界与异常

1. **余额不足硬阻断**：取出、「从储蓄支付」、转账超出该账户余额 → 前端即时标红 + 后端事务内二次校验，并提示可用金额（多账户下按账户判断，不依赖前端数字）；后端校验走**余额原子扣减 / 行锁**，不做「先查后写」
2. 编辑 / 删除导致余额为负 → 阻止。**校验口径是该账户当前余额**（编辑发生在当下，不做历史时点重算）；「从储蓄支付」改金额时上限 = 当前余额 + 原取出金额，超限阻断并提示上限，给出「先存入」或「改从其他账户支付（删除重录）」两个出路。金额必须 > 0；只改备注 / 日期不触发余额校验，改日期跨月时重算原月与新月的预算与统计。编辑时**方向一律不可改**（`in` ↔ `out` 只能删除后重录）
3. 组合记录（从储蓄支付 / 到账即存）任一侧删改 → 弹窗告知「将同时撤销/调整对应的 XX」，**成对删除、成对修改**；业务日期两侧强制一致，否则「本月支出」与「本月净增」会跨月错位。owner 可编辑他人录入的组合记录，提示中注明录入人，`openid` 不因 owner 编辑而改变
4. **成员退出**：收支流水软作废（`status=0`，保留 `voided_*` 审计痕迹），**储蓄流水与成对记录整对保留、不回滚**。原则是「**记账行为可以作废，资金位置不能作废**」——储蓄余额是派生的 `Σ存入−Σ取出`，作废一条储蓄流水等于改资产现状。具体约束：
   - `voidByMember` 必须排除**任一方向**的成对记录：「从储蓄支付」的支出、「到账即存」的收入都通过 `saving_record.linked_transaction_id` 关联，只排除支出侧会造出"收入被作废、存入还在"的新错账
   - 由此可能出现 `储蓄余额 > 累计结余`，属 5.2 场景 D 的既定状态，**不提示、不校验**（本节第 9 条）
   - **操作人展示**：`family_member` 是物理删行，历史流水靠 `saving_record.operator_name` 昵称快照（收支侧同理）展示"谁记的"，不依赖成员行存在
   - **组合记录转只读**：账单侧已作废时，关联的储蓄流水不可编辑 / 不可删除，「关联账单」入口隐藏或置灰，避免 owner 单方面删掉取出导致余额回退（6.2）
   - **不区分主动退出与被移除**（结果一致，只在 `void_reason` 记录原因）；退出成员本人已不是 member，`/family/{id}/**` 的成员校验会将其挡掉，数据仅在家庭内可见；彻底清除只能走「家庭解散」（本节第 5 条）
5. 家庭解散：账户与流水**物理删除**（不走逻辑删除）
6. 账户转账：从/到账户不能相同；转出余额不足硬阻断；写两条方向相反的记录并共享 `link_id`，成对删改、方向不可改；储蓄余额、本月净增、预算与统计均不受影响
7. 账户停用（**仅自定义账户**）：余额仍计入总额，可随时启用或转出；账户逻辑删除后，历史流水的账户名仍需展示（聚合查询需带出 `deleted=1` 的账户，但不进入可选列表）
8. 更新余额：`δ = 0` 不允许提交；必须勾选「我确认这是账户当前的实际余额」；同一账户 24h 内二次校准需二次确认并显示上次时间与差额；记录 `source=adjust`、金额不可编辑，只能删除后重新校准，删除后余额自动回退
9. **不做跨账本校验**：存入多少都不拦截、不提示"账外资金/手头不够/可能漏记收入"；账户实际值与账面不符时只由用户主动「更新余额」处理，系统不自动介入（决策 10、11）。更新余额不生成账单，不进预算 / 统计 / 分类占比 / 明细页

## 12. 验收要点

1. 存入 3,000 后：本月收入 / 支出 / 分类占比 / 预算全部不变，所选账户与储蓄余额各 +3,000
2. 取出 2,000 后：收入 / 支出均不变，所选账户与储蓄余额各 −2,000
3. 取出超过该账户余额：即时标红 + 按钮置灰，硬阻断，提示可取出金额
4. 未记收入时存入 2,000：**允许且无任何提示**，累计结余仍按实际显示
5. 从储蓄支付 8,000：一次生成支出 8,000 + 取出 8,000，本月支出 +8,000、预算同步消耗、储蓄余额 −8,000
6. 删除该笔支出：弹窗告知并同时撤销取出，储蓄余额增加 8,000
7. 修改该笔支出为 5,000：对应取出同步改为 5,000，储蓄余额相应增加 3,000
8. 成员退出：其收支流水软作废（`status=0`），储蓄记录与**成对记录整对保留**（「从储蓄支付」的支出、「到账即存」的收入都不作废），储蓄余额不变；这些组合记录的储蓄侧转只读（不可编辑 / 删除），操作人显示退出前的昵称快照
9. 收入到账即存：工资收入勾选「同时存入家庭储蓄」→ 一次生成「收入 + 存入」；全部分类同一套文案
10. owner 编辑成员录入的「从储蓄支付」支出 → 提示含录入人姓名，取出同步修改，`openid` 仍为成员而非 owner
11. 组合记录改业务日期 → 两侧日期同步；尝试把取出改成存入被拒（需删除组合后重录）
12. 账户间转账 5,000（国债 → 活期）：生成 `transfer_out` + `transfer_in` 两条、共享 `link_id`；储蓄余额、本月净增、预算、统计均不变；删任一条则两条一起消失
13. 账户删除：余额 > 0 被拒并提示先转出；转出到 0 后可逻辑删除，历史流水仍显示该账户名
14. 账户停用（**仅自定义账户可停用**，预置账户不可停用/改名/删除）：不再出现在存取 / 支付 / 转账的账户列表，但其余额仍计入储蓄余额总额
15. 按账户筛选：储蓄页选「国债」→ 储蓄余额与流水只显示该账户；切回「全部」恢复总额，各账户余额之和恒等于储蓄余额
16. 账户上限：自定义账户达 20 个后新建按钮置灰，提示「最多 20 个自定义账户」（含 5 个预置共 25 个）
17. **两本账不交叉**：储蓄余额大于累计结余（记账前存款未录入）时，界面不提示、不校验、不解释（5.2 场景 D）
18. **无收益入口**：全局不存在「收益 / 自动估值」按钮或勾选；唯一与估值相关的操作是显式的「更新余额」，且它不产生任何收支记录
19. 更新余额：账面 12,000、输入 13,000 → 自动生成「存入 1,000（`source=adjust`，标「余额调整」）」，储蓄余额 13,000、本月净增 +1,000，**累计结余、预算、分类占比不变**、明细页无记录；输入 11,400 则对称生成「取出 600」
20. 更新余额边界：δ = 0 → 提交置灰；未勾选「我确认这是当前实际余额」不能提交；负数被拒；24h 内二次校准需二次确认；调整记录金额不可编辑，删除后余额回退
21. 从储蓄支付改金额：调大上限 = 该账户当前余额 + 原取出金额；超限被阻断并提示上限与两个出路；金额必须 > 0；只改备注 / 日期不触发余额校验，改日期跨月则原月与新月统计均重算
22. 组合记录边界：编辑时**储蓄账户不可改**（要换只能删除后重录）；配对取出已不存在 → 拒绝保存并提示删除后重记；后端校验走余额原子扣减，两笔并发不能同时穿透
23. 编辑组合记录：记账弹层里的开关为只读态（不可取消勾选）、储蓄账户不可切换；删除确认文案写明「同时撤销取出 ¥X，余额从 ¥A 回到 ¥B」
24. 支付金额超过所选账户余额：预览区变红显示「不足 ¥X」、输入框描边红、按钮置灰但保留，点击提示上限；后端并发下同样被拦住
25. 启用账户仅 1 个时转账入口置灰并提示；停用账户不出现在新增存取 / 支付 / 转账列表，但在储蓄页筛选区可见、可查历史流水
26. 记账页两个开关的默认账户 = 上次在记账页用过的账户，与储蓄页当前浏览的账户无关；「更新余额」入口在余额卡上常驻可见，全部视角点击先弹账户选择
27. 布局与状态：首页「存入」按钮不触发卡片跳转（`catchtap`）；流水两行式、账户名超 6 字截断；月份分组头带当月小计；余额卡标题随账户筛选切换；首屏骨架屏、分页「加载中 / 没有更多了」、加载失败可重试、保存中防重复点击
28. 视觉与工程复用：储蓄页复用 `.page` / `navigation-bar` / `.trans` 行骨架与 `.date-head` 小计；取出色用新增 `--saving-out` 而非 `--expense`；账户区只用 `scroll-view scroll-x` 包账户卡、流水走整页滚动；底部操作条留 `.action-clear` 占位
29. 记账表单：「从储蓄支付」开关位于**金额与信息卡之间**（不贴表单底部）；折叠卡两行、≤120rpx；点折叠卡打开半屏账户面板；沿用系统数字键盘与流末保存按钮，保存中拦截重复点击
30. 预置账户：**活期（默认）、定期、国债、基金、保险**共 5 个，不含「其他」；新增存取 / 支付 / 转账未选账户时落到「活期」；保险账户余额按现金价值口径，退保 / 减保后靠「更新余额」校准

## 附录 A：为什么不做「全账户模型」（设计取舍）

> 记录一个被否决的方案，避免将来重复讨论。

**提案**：把「现金」也做成账户——收入 = 外部 → 现金账户，支出 = 现金账户 → 外部，存钱 = 现金账户 → 储蓄账户（即复式记账）。

**它能带来**：概念统一（只剩"外部进出"与"账户间转账"）、真实余额可追踪、可扩展信用卡 / 多币种 / 净资产。

**放弃原因**：

| 成本 | 说明 |
|---|---|
| 每笔记账多一步 | 必须选"从哪个账户出"，家庭高频小额记账难以接受 |
| 余额会漂 | 漏记一笔就偏，需为**所有**账户提供余额校准（本方案只在储蓄账户内提供「更新余额」），且用户会逐渐不信任这个数字 |
| 需要期初余额 | 每个账户要有起点，带来期初日期、多成员、修改回溯等复杂度 |
| 账户归属 | 爸爸微信、妈妈银行卡各自私有，共享账本里权限与统计口径要重做 |
| 改造量 | 收入/支出降级为虚拟账户，分类、预算、统计、明细全部按新口径重算，生产库需迁移（约 2~3 倍工作量） |

**本期采用**：**两本账**——收支流水账（`transaction`）+ 独立的储蓄模块（`saving_record`）。两者只在记账页的两个开关处交汇（从储蓄支付 / 到账即存），其余时间互不干涉、互不校验。

**何时重新考虑**：当明确需要"微信 / 银行卡 / 支付宝各自余额"且愿意维护时。届时 `saving_account` 已具备账户模型，只需补「现金账户 + 期初余额」；余额校准机制已存在（6.9），可直接复用。

## 附录 B：术语速查与示例

> **示例家庭**：累计结余 ¥20,000、储蓄余额 ¥12,000，本月无流水。金额按整数分存储，下文 ¥ 仅为展示。

### B.1 术语表

| 概念 | 定义 | 例子 |
|---|---|---|
| 收入 / 支出 | 与家庭外部之间的钱进出，只影响**累计结余** | 记收入 10,000 → 结余 30,000；记支出 200 → 结余 19,800 |
| 业务日期 | 事情实际发生的日期，统计"本月"一律按它 | 10-31 补记 10-01 餐费 → 计入 10 月 |
| 储蓄 | 与收支**完全独立**的第二本账，只记进出 | 把 5,300 挪进国债，收入与支出都不变 |
| 储蓄余额 | 派生值 `Σ(存入+转入) − Σ(取出+转出)`，不落库；只在用户「更新余额」时被校准 | 12,000 再存入 5,300 → 17,300 |
| 存入 / 取出 | 往储蓄里放钱 / 从储蓄里拿钱回手头，只改储蓄余额 | — |
| 更新余额 | 只填账户当前实际值，差额方向由系统判定，生成一条 `source=adjust` 流水 | 账面 12,000、实际 13,000 → 自动记「余额调整 +1,000」 |
| 从储蓄支付 | 支出表单里勾选，一次生成 `支出 + 取出` 的组合记录 | 买家电 8,000 → 结余 −8,000、储蓄 −8,000 |
| 账户转账 | 储蓄内部换账户，两条方向相反的流水，净影响 0 | 国债 → 活期 5,000，总额不变 |
| 本月净增 | 本月存入 − 本月取出（含「从储蓄支付」与「更新余额」的流水；转账不计） | 存 3,000、取 1,200 → +1,800 |
| 组合记录 | 必须同时存在、同时删改的两条记录（`linked_transaction_id` 跨表 / `link_id` 同表） | 支出 8,000 ↔ 取出 8,000 |

### B.2 储蓄与收支的边界

| 问题 | 结论 |
|---|---|
| 利息 / 收益怎么记？ | **不记收支**（决策 10） |
| 账户市值涨了怎么办？ | 想反映到余额就点「更新余额」，只填实际值；不进收支（6.9） |
| 储蓄余额比累计结余还大？ | **正常**，记账前的存款未录入；两本账不交叉校验（5.2 场景 D） |
| 存入超支要不要提示？ | **不提示**，不做账外资金校验（决策 10） |
| 花储蓄里的钱？ | 用「从储蓄支付」，保证支出不漏记 |

### B.3 数字怎么变

> 每行都从示例家庭（20,000 / 12,000）出发，行间不累加；每行假设本月无其他流水。

| 动作 | 累计结余 | 储蓄余额 | 为什么 |
|---|---|---|---|
| 支出 200（买菜） | 19,800 | 12,000 | 花日常的钱，储蓄没动 |
| 收入 10,000（工资） | 30,000 | 12,000 | 钱进日常账，储蓄没动 |
| 存入 3,000 | 20,000 | 15,000 | 只动储蓄余额 |
| 取出 1,200 | 20,000 | 10,800 | 只动储蓄余额 |
| 从储蓄支付 8,000 | 12,000 | 4,000 | 钱真花了：支出 + 取出 |
| 更新余额 12,000 → 13,000 | 20,000 | 13,000 | 只记「余额调整 +1,000」 |
| 账户转账 5,000 | 20,000 | 12,000（总额不变） | 仅内部搬家 |

### B.4 操作示例：发工资 10,000，存 5,300 到国债

> 这是**两件事**：家里进钱（收入）+ 换个位置（存入），拆成两步。

| 步骤 | 操作 | 结果 |
|---|---|---|
| 1 | 记**收入** 10,000 / 工资 | 累计结余 30,000；储蓄余额 12,000；不生成储蓄流水 |
| 2 | 储蓄页「存入」5,300 / 账户「国债」 | 储蓄余额 17,300；本月净增 +5,300；累计结余 30,000 不变 |

- 第 1 步的「同时存入家庭储蓄」保持**关闭**——工资已进日常账，勾选等于再存一次（决策 8）
- 第 2 步无任何提示（不做超支校验），不生成收入/支出、不进明细页
- 页面表现：储蓄卡显示 `¥17,300`、`本月 +5,300`

### B.5 四个易错点

1. **存入不会让家庭变富**：只增加储蓄余额，累计结余不变；把存入当收入会把同一笔工资计两次。
2. **两本账本来就不相等**：储蓄余额可能大于累计结余，不是 bug，界面不提示。
3. **「从储蓄支付」≠「取出」**：花了钱用前者（写支出 + 取出）；只是拿回手头、还没花用后者（只写取出）。
4. **「更新余额」≠「取出」**：更新余额只改账面、钱没动；取出是把钱真的拿回手头。
